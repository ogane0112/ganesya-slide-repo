# デッキを作る

メモや下書きからデッキを作るときの手順と、原稿の書き方のルール。
テーマの仕様は CLAUDE.md の「デザイン」、要件は `docs/requirements.md` を参照。

## 手順

1. **種別とslugを決める**
   - 学習(自分が学んだことのメモ)/ まとめ(調べたことの整理・記事)/ 講座(人に教える、演習あり)
   - slug は英小文字・数字・ハイフン。日付(YYYY-MM-)は自動で付く
2. **雛形から作る**(手でフォルダを作らない)
   ```bash
   npm run new -- <slug> --category まとめ --title "タイトル"
   ```
   → `decks/<learning|summary|course>/YYYY-MM-<slug>/slides.md` と `images/` ができる
3. **frontmatter を埋める**: `tags` を空のままにしない。`status` は書き始めは `draft`
4. **構成を決めてから本文を書く**(下の「構成」)
5. **検査する**
   ```bash
   npm run validate
   npm run check -- decks/<種別>/<フォルダ>
   ```
   - 要対応が0件になるまで直す。レポートは `reports/report.md`
   - Jev の呼び出しに失敗しても精査がスキップされるだけで、レイアウト検査は続く。スキップされたらユーザーに伝える
6. **見た目を目で確認する**: `reports/decks/.../contact.png`(一覧)と `slides/slide-NNN.png` を Read で開く。
   検査を通っても崩れていることがある(図の位置ずれ、変な折り返し、スカスカ・ギチギチ)

Chromium が無いと言われたら `npx playwright install chromium`。`tsx` が無いと言われたら `npm install`。

## 構成

- 1枚目はタイトルスライド(雛形のまま `_class: title` と `<div class="tag">`)。サブタイトルに「ひとことで言うと」を置く
- 2枚目で「それは何か」を一言で。最後は `summary` の吹き出しでまとめ、出典は `ref` で付ける
- 流れの目安: 何か → 仕組み・特徴 → 例 → 比較・使い分け → 注意点 → (今後)→ まとめ
- 1枚 = 1メッセージ。見出しはそのスライドで言いたいことにする(「概要」「その他」のような箱の名前にしない)

## 1枚あたりの分量(1280×720、本文28px)

L-04(行数・文字数の上限)は未決なので、当面は次を目安にする。

- 箇条書きは 3〜4 個、入れ子は1段まで。1項目は1行(全角30字程度)に収める
- 表は 3〜4 行 × 2〜3 列。セルは短い言葉だけ
- 吹き出しは1枚に1つ、2行まで
- 「箇条書き + 表」「コード + 箇条書き」のように大物を2つ載せない。載せるなら片方を吹き出しにする

## 吹き出しの使い分け

| クラス | 使うとき |
| --- | --- |
| `point` 💡 | そのスライドで一番言いたいこと |
| `warn` ⚠️ | 落とし穴・変わりうる情報・**筆者の予想**(事実と区別する) |
| `note` 📝 | 補足・豆知識 |
| `summary` ✅ | まとめ(最後のスライド、または節のまとめ) |
| `ref` 🔗 | 出典・参考リンク(20pxの小さい字になる) |

div の中で Markdown を使うときは、開きタグの後と閉じタグの前に空行を入れる。

## やってはいけないこと

- **アスキーアートの図を書かない**。全角・半角の幅がフォントで揃わず崩れる。表か箇条書きにする
  (流れの図は「A → B → C」の1行、分岐は「入力 | 判断 | 行き先」の表が扱いやすい)
- 文字サイズを CSS で小さくして詰め込まない(L-03 で20px未満は違反)。分量が多ければスライドを分ける
- 公開リポジトリなので、職場の情報・個人情報・APIキーを書かない

## 元ネタのメモが足りないとき

メモは箇条書きの断片のことが多い。スライドにするときは次を補う。

- **事実・数字**: まずリポジトリ内(`docs/requirements.md` など)から探し、出典を `ref` に書く。見つからない数字は作らない
- **例**: 抽象的な説明には具体例を1つ付ける(表の1行でよい)
- **メモの推測・感想**(「おそらく〜」「〜らしい」): 事実のように書き換えず、`warn` で「筆者の予想」と明記する
- **メモに無いが読者が迷う点**(苦手なこと・注意点など): 1枚足してよい。足した内容は完了報告でユーザーに伝える
